## ۱. معماری استک FRP بر بستر GRE

در پنل هاشم، ارتباط بین سرور ایران و سرور خارج از یک معماری دو لایه هیبریدی بهره می‌برد:
```text
┌─────────────────┐                                  ┌─────────────────┐
│   سرور ایران    │                                  │   سرور خارج     │
│  (Iran Server)  │                                  │ (Foreign Server)│
│                 │                                  │                 │
│  ┌───────────┐  │   Layer 3 Point-to-Point (GRE)   │  ┌───────────┐  │
│  │ gre-tun   │◄─┼──────────────────────────────────┼─►│ gre-tun   │  │
│  │ 10.10.0.1 │  │       Kernel Raw Protocol 47     │  │ 10.10.0.2 │  │
│  └─────┬─────┘  │                                  │  └─────▲─────┘  │
│        │        │   FRP Reverse Tunnel Stack       │        │        │
│  ┌─────▼─────┐  │  [TCP / KCP / QUIC / WS / WSS]   │  ┌─────┴─────┐  │
│  │   frps    │◄─┼──────────────────────────────────┼─►│   frpc    │  │
│  │ Listeners │  │   + Encryption / Compression     │  │ Proxies   │  │
│  └───────────┘  │   + PROXY Protocol v2 Injection  │  └───────────┘  │
└─────────────────┘                                  └─────────────────┘
```

1. **لایه ۳ شبکه (Network Layer):** اینترفیس GRE خام ارتباط پایه پوینت-تو-پوینت را با حداقل Latency (زیر ۱ میلی‌ثانیه اورهد) برقرار می‌کند.
2. **لایه ترنسپورت پروکسی (Application/Transport Layer):** هسته FRP روی این بستر قرار گرفته و وظیفه ریورس پروکسی پورت‌ها، مالتی‌پلکس کردن اتصالات، و مبهم‌سازی/رمزنگاری را بر عهده دارد.

## ۲. بررسی تخصصی ۵ پروتکل ترنسپورت

### ۱. TCP (Standard Multiplexed)
* **مکانیزم فنی:** اتصالات کلاینت FRP به سرور ایران از طریق یک جریان استاندارد TCP باز می‌شوند و با استفاده از Yamux/Smux چندین اتصال کاربر درون استخر کانکشن‌های TCP مالتی‌پلکس می‌شوند.
* **نکته (tcpMux):** مقدار پیش‌فرض `transport.tcpMux` در هاشم **خاموش (false)** است تا حداکثر سرعت حاصل شود (روی GRE تقریباً سرعت را نصف می‌کند). فقط با `hashem perf tcpmux on` فعال کنید و مقدار آن باید روی سرور ایران و تمام سرورهای خارج **یکسان** باشد؛ در غیر این صورت frpc با خطای `connect to server error: EOF` وارد نمی‌شود.
* **مزایا:**
  * حداقل مصرف منابع پردازنده (CPU) و رم.
  * پایداری کامل در شبکه‌هایی که پروتکل UDP به شدت محدود یا Throttle شده است.
  * سازگاری ۱۰۰٪ با تمامی دیتاسنترها و روت‌های شبکه.
* **معایب:** در صورت بروز پکت‌لاس شدید (Packet Loss > 10%)، مکانیزم TCP Congestion Control سرعت کل جریان را کاهش می‌دهد (Head-of-Line Blocking).
* **بهترین سناریو:** اینترنت‌های ثابت با پکت‌لاس کم (شاتل، مخابرات، آسیاتک، رسپینا) و شرایطی که سیستم فیلترینگ پکت‌های UDP را دراپ می‌کند.

---

### ۲. KCP (ARQ over UDP)
* **مکانیزم فنی:** یک پروتکل انتقال داده سریع مبتنی بر UDP با الگوریتم اختصاصی ARQ (Automatic Repeat reQuest). برخلاف الگوریتم TCP که در زمان پکت‌لاس سرعت را نصف می‌کند، KCP پکت‌های از دست رفته را فوراً و با سرعت چند برابر باز ارسال می‌کند.
* **مزایا:**
  * مقاومت فوق‌العاده در برابر پکت‌لاس‌های سنگین (حتی تا ۳۰ الی ۴۰ درصد).
  * کاهش مشهود پینگ و جیتر (Jitter) در گیمینگ و تماس‌های صوتی/تصویری.
  * واکنش آنی به قطعی‌های موقت شبکه.
* **معایب:** مصرف پهنای باند را بین ۱۰ تا ۲۰ درصد به دلیل باز ارسال مکرر افزایش می‌دهد؛ در صورتی که دیتاسنتر یا ISP پروتکل UDP را مسدود کرده باشد کارایی ندارد.
* **بهترین سناریو:** اینترنت همراه اول (MCI) و ایرانسل در ساعات اوج مصرف و زمان‌هایی که پکت‌لاس شدید روی بستر بین‌الملل رخ می‌دهد.

---

### ۳. QUIC (IETF over UDP)
* **مکانیزم فنی:** پروتکل نسل جدید اینترنت (پایه HTTP/3) که بر بستر UDP اجرا شده و از ابتدا برای سرعت بالا، هندشیک 0-RTT و حذف کامل Head-of-line Blocking طراحی شده است.
* **مزایا:**
  * برقراری اتصال بسیار سریع بدون تاخیر چندمرحله‌ای (Zero Round-Trip Time).
  * مالتی‌پلکسینگ مستقل استریم‌ها: اگر پکت یک کاربر گم شود، ترافیک سایر کاربران متوقف نمی‌شود.
  * پایداری بالا در زمان تغییر مسیرهای روتینگ شبکه (Connection Migration).
* **معایب:** نیاز به پایداری پورت UDP روی بستر شبکه دارد.
* **بهترین سناریو:** وب‌گردی مدرن، استریم ویدیو، دانلود با چندین کانکشن همزمان و شبکه‌های مدرن 4G/5G.

---

### ۴. WebSocket (HTTP Upgrade)
* **مکانیزم فنی:** جریان ترافیک تانل در قالب درخواست‌های استاندارد HTTP/1.1 Upgrade به وب‌سوکت ارسال می‌شود.
* **مزایا:**
  * ظاهر کاملاً شبیه به وب‌سایت‌های عادی اینترنتی.
  * عبور موفق از فایروال‌ها و فیلترهایی که ترافیک‌های غیر از پورت‌های وب (۸۰/۸۰۸۰) را شناسایی و قطع می‌کنند.
* **معایب:** اورهد هدرهای HTTP و بازدهی کمی پایین‌تر نسبت به TCP خام.
* **بهترین سناریو:** شرکت‌ها و مراکزی که فایروال‌های سختگیرانه دارند و فقط ترافیک وب را مجاز می‌دانند.

---

### ۵. WSS (TLS-Obfuscated WebSocket)
* **مکانیزم فنی:** انتقال فریم‌های وب‌سوکت درون یک نشست کاملاً رمزنگاری‌شده با پروتکل استاندارد TLS 1.3 و هندشیک معتبر کریپتوگرافیک.
* **مزایا:**
  * بالاترین سطح مقاومت در برابر سیستم‌های فیلترینگ عمیق (Deep Packet Inspection / DPI).
  * محتوای تانل به هیچ عنوان توسط شنود بین‌راهی قابل آنالیز یا تشخیص نیست.
* **معایب:** مصرف CPU کمی بالاتر به علت رمزنگاری دوگانه TLS.
* **بهترین سناریو:** شرایط فیلترینگ فوق‌العاده شدید یا زمان‌هایی که ترافیک تانل‌های ساده بلافاصله شناسایی و قطع (Disrupt) می‌شوند.

## ۳. قابلیت‌های پیشرفته FRP

### 🔒 رمزنگاری (useEncryption)
* با فعال‌سازی گزینه `transport.useEncryption = true`، ترافیک بین کلاینت خارج و سرور ایران با کلیدهای امن رمزنگاری می‌شود.
* **چه زمانی روشن کنیم؟** زمانی که نمی‌خواهید داده‌های رد و بدل شده در مسیر میانی توسط ISP یا سنورها شنود یا تحلیل رفتار شوند.

### 🗜️ فشرده‌سازی (useCompression)
* با فعال‌سازی گزینه `transport.useCompression = true`، داده‌های متنی و استریم‌های بدون فشرده‌سازی قبل از ارسال با الگوریتم فوق‌سریع **Snappy** فشرده می‌شوند.
* **چه زمانی روشن کنیم؟** برای ترافیک‌های متنی، وب‌سایت‌های بدون HTTPS، داده‌های دیتابیس و کاهش حجم مصرفی تانل.
* **چه زمانی خاموش باشد؟** در صورتی که اکثر کاربران در حال تماشای ویدیو (YouTube/Instagram) یا دانلود فایل‌های فشرده (Zip/Rar/Mp4) هستند، فشرده‌سازی تاثیری در کاهش حجم ندارد و فقط پردازنده را درگیر می‌کند.

### 🌐 پروتکل پروکسی نسخه ۲ (PROXY Protocol v2)
* با فعال‌سازی این قابلیت (`transport.proxyProtocolVersion = "v2"`):
  * هسته FRP کلاینت به ازای هر اتصال ورودی، یک هدر باینری سبک شامل **آی‌پی و پورت واقعی کاربر ایرانی** به پکت اضافه می‌کند.
  * پنل‌های ویتوری و اکس‌ری (نظیر مرزبان، پاسارگاد، سنایی و 3X-UI) با فعال‌سازی گزینه `Accept Proxy Protocol` آی‌پی واقعی تک‌تک کاربران را می‌بینند.
* **نتیجه:**
  * کارکرد دقیق محدودیت تعداد آی‌پی همزمان (IP Limit).
  * نمایش دقیق آمار آنلاین بودن کاربران به تفکیک IP.
  * ثبت لاگ‌های واقعی ترافیک در هسته Xray.

## ۴. ماتریس انتخاب پروتکل بر اساس اپراتورهای ایران

| اپراتور / وضعیت شبکه | ترنسپورت پیشنهادی | رمزنگاری | فشرده‌سازی | PROXY Protocol |
| :--- | :--- | :--- | :--- | :--- |
| **همراه اول (MCI) - پکت‌لاس بالا** | **`kcp`** | خاموش | خاموش | **v2** |
| **ایرانسل (Irancell) - پایدار/عادی** | **`quic`** یا **`tcp`** | خاموش | خاموش | **v2** |
| **مخابرات و شاتل (Fixed Broadband)** | **`tcp`** | خاموش | خاموش | **v2** |
| **فیلترینگ شدید / اختلال روی پورت‌ها** | **`wss`** | روشن | خاموش | **v2** |
| **کاهش مصرف حجم در ترافیک متنی** | **`tcp`** | خاموش | روشن | **v2** |

## ۵. نحوه تنظیم در وب پنل و ترمینال

### الف) از طریق وب پنل (Web Dashboard):
1. **هنگام اتصال سرور خارج (Foreign Join):**
   - در تب **Setup** زیرمجموعه اتصال، از منوی کشویی **FRP Transport Protocol** پروتکل مورد نظر (`tcp`, `kcp`, `quic`, `websocket`, `wss`) را انتخاب کنید.
   - تیک‌های **Encryption**، **Compression** یا **PROXY Protocol v2** را مطابق نیاز علامت بزنید.
   - دکمه **Connect to Iran** را کلیک کنید.
2. **برای تانل‌های موجود (Edit Peer):**
   - به تب **Tunnel** بروید و روی تانل مورد نظر دکمه **Edit** را بزنید.
   - پروتکل ترنسپورت و تیک‌های امنیتی را تغییر داده و **Save** کنید؛ تنظیمات بلافاصله اعمال می‌شوند.

---

### ب) از طریق خط فرمان (CLI Terminal):

#### ۱. راه‌اندازی سرور خارج با KCP و PROXY Protocol v2:
```bash
hashem setup-foreign \
  --bundle "hsh1_..." \
  --ports "443, 2083" \
  --frp-transport kcp \
  --proxy-protocol v2
```

#### ۲. راه‌اندازی سرور خارج با WSS، رمزنگاری و فشرده‌سازی:
```bash
hashem setup-foreign \
  --bundle "hsh1_..." \
  --ports "443, 8443" \
  --frp-transport wss \
  --encrypt \
  --compress \
  --proxy-protocol v2
```

#### ۳. ویرایش تانل فعال در سرور خارج یا تغییر تنظیمات پیر در سرور ایران:
```bash
# تغییر ترنسپورت به QUIC و فعال‌سازی PROXY Protocol v2
hashem edit-peer --id 1 --frp-transport quic --proxy-protocol v2

# فعال‌سازی رمزنگاری و فشرده‌سازی
hashem edit-peer --id 1 --encrypt --compress
```
