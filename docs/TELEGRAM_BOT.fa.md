# ربات تلگرام (هاشم پرو)

پنل را از یک چت تلگرام اداره کنید: وضعیت تونل‌ها، ری‌استارت، نگهبان،
Autopilot، هشدارها، مشتری‌ها، عیب‌یابی، نسخه‌های پشتیبان، لاگ‌ها،
به‌روزرسانی، و هر درخواست دیگری به API پنل.

[English](TELEGRAM_BOT.md)

## راه‌اندازی

1. در تلگرام به **@BotFather** پیام بدهید، `/newbot` را بفرستید و توکنی را که
   می‌دهد کپی کنید. **برای هر سرور یک ربات جدا** بسازید: اگر دو سرور با یک
   توکن کار کنند پیام‌های همدیگر را می‌گیرند (پنل می‌نویسد «another program
   reads this bot's messages»).
2. در پنل: **Settings → Alerts & monitoring → Telegram bot**. توکن را بگذارید،
   زبان ربات را انتخاب کنید، **Enable the bot** را بزنید و **Save** کنید.
3. **Admin** یا **Viewer** را انتخاب کنید و **Get a Pairing Code** را بزنید.
   پیوندی را که نشان می‌دهد در تلگرام باز کنید (یا `/start CODE` را برای ربات
   بفرستید). کد یک بار و تا ۱۰ دقیقه کار می‌کند. هر حسابی را که می‌خواهید با
   ربات کار کند جدا جفت کنید.

نشان کنار کارت می‌گوید ربات در حال اجراست یا نه، و آخرین خطایش چه بوده.
**Send Test** توکن را بررسی می‌کند و برای همه‌ی گیرنده‌های هشدار پیام
می‌فرستد.

### یک ربات برای همه‌چیز

همین یک ربات هم منو را دارد و هم همه‌ی هشدارها را می‌فرستد: نگهبان، Autopilot
و هشدارهای بیرونی. هشدارها به همه‌ی حساب‌های جفت‌شده می‌روند، و اگر روی کارت
**چت هشدار** گذاشته باشید (گروه یا کانال؛ ربات را به آن اضافه کنید) به آن هم.
هر حساب می‌تواند هشدارهای خودش را در ربات (🔔 هشدارها) یا روی کارت بی‌صدا کند.

نسخه‌های قبل یک توکن دوم در تب نگهبان داشتند. موقع به‌روزرسانی، رباتی که روشن
است و حساب جفت‌شده دارد می‌ماند، وگرنه ربات نگهبان؛ توکن دیگر بدون استفاده در
`telegram_bot.json` نگه داشته می‌شود.

### وقتی تلگرام روی سرور بسته است

کاری لازم نیست: در مسیر **خودکار** ربات اول مستقیم از همین سرور می‌رود و اگر
نشد، از تونل‌های همین سرور (اول تونل‌های سالم). کارت می‌نویسد از کدام راه وصل
است. **فقط مستقیم** و یک تونل مشخص (و بعد مستقیم) انتخاب‌های دیگرند.

اتصال را پنلِ سرور خارجِ همان تونل برقرار می‌کند، از راه Peer Link که پنل‌ها
از قبل دارند، و فقط به تلگرام و Cloudflare. پس یک تونل FRP، Backhaul یا GRE
لازم است که سرور خارجش همین پنل را داشته باشد. تونل‌های Xray، باقر و اسپوف این
راه را ندارند.

## چه کارهایی می‌کند

| منو | چه می‌دهد |
|---|---|
| 📊 وضعیت | وضعیت، تأخیر و ترافیک هر تونل، و دلیل خراب بودنش |
| 🔗 تونل‌ها | همه‌ی تونل‌های این سرور (تونل‌های هاب، تونل خود سرور خارج و هاب‌های ایران دیگرش، Xray، باقر، اسپوف): جزئیات؛ ری‌استارت تونل، ری‌استارت GRE، پینگ، تغییر نام، حذف؛ ری‌استارت یا توقف لینک Xray |
| 🗂 نودها | روی پنل مرکزی: نودها، وضعیت و تعداد تونلشان (فقط دیدن) |
| 🐶 نگهبان | روشن/خاموش، ری‌استارت خودکار، پیام آزمایشی، ری‌استارت همه‌ی تونل‌ها، گرفتن نسخه پشتیبان، وضعیت هر تونل |
| 💾 نسخه پشتیبان | ۱۰ نسخه‌ی آخر: دانلود (فایل رمزنگاری‌شده) و بازگردانی |
| 🤖 Autopilot | روشن/خاموش، حامل و وضعیت هر تونل، جابه‌جایی‌های اخیر |
| 🔔 هشدارها | روشن/خاموش، نسخه‌ی تلگرام، هشدار وضعیت ضعیف، آزمایش؛ بی‌صدا کردن هشدار برای همین حساب |
| 👥 مشتری‌ها | مصرف، تاریخ پایان و لینک‌های هر مشتری؛ توقف/فعال‌سازی، تمدید، صفر کردن مصرف، حذف |
| 🩺 عیب‌یابی | آخرین گزارش، اجرای تازه، تعمیر سریع |
| 🛠 ابزارها | بهینه‌سازی/برگرداندن تنظیمات شبکه، وضعیت تنظیم، تست سلامت تونل‌ها، پیشنهاد حامل، محدودیت‌ها، Sentinel |
| 📜 لاگ | ۴۰۰ خط آخر لاگ سرویس‌ها، به‌صورت فایل |
| ❗️ خطاها | ۲۰ خطای آخر پنل |
| ⬆️ آپدیت | نسخه‌ی فعلی و آخرین نسخه، آپدیت فوری (ربات خبر می‌دهد وقتی پنل برگشت)؛ **سرورهای دیگر**: هاب‌های ایرانِ متصل و سرورهای خارج با نسخه‌شان، و آپدیت همه‌ی آن‌هایی که نسخه‌ی دیگری دارند |
| 🌐 کلاستر | وضعیت کلاستر |
| 🔑 لایسنس | وضعیت لایسنس و قابلیت‌های Pro (فقط دیدن) |

هر کار دیگری که پنل دارد با **`/api`** در دسترس است، یعنی یک درخواست مستقیم به
API پنل ([API.md](API.md)):

```
/api GET /api/peers
/api POST /api/action {"action":"ping","peer_id":2}
/api PATCH /api/peers {"id":2,"ports":"443, 8443"}
```

هر درخواستی جز `GET` قبل از اجرا یک بار دیگر تأیید می‌خواهد.

دستورها: `/menu /status /tunnels /watchdog /autopilot /customers /doctor
/errors /logs /update /api /cancel /help /id`.

## چه کسی می‌تواند از آن استفاده کند

- فقط حساب‌هایی که از پنل جفت شده‌اند، و فقط در **چت خصوصی** با ربات. گروه‌ها
  و کانال‌ها نادیده گرفته می‌شوند تا هیچ‌کس در یک گروه نتواند به ربات دستور
  بدهد. حسابی که جفت نشده فقط یک جواب کوتاه با شناسه‌ی تلگرامش می‌گیرد.
- **Admin** همه‌ی کارهای بالا را می‌کند؛ **Viewer** فقط منوها را می‌بیند (نه `/api`، کلاستر، محدودیت‌ها، Sentinel یا پیشنهاد حامل، چون پاسخ کاملشان ممکن است توکن تونل و کلید داشته باشد).
- هر دکمه برچسب سرور خودش را دارد: اگر دو سرور یک توکن ربات مشترک داشته باشند، دکمه‌ی پیام یک سرور روی سرور دیگر کاری نمی‌کند.
- هر جفت‌سازی تازه به ادمین‌های دیگر خبر داده می‌شود. حذف حساب یا تغییر نقشش
  روی همان کارت است.
- پنج کد اشتباه در ده دقیقه، و آن حساب تا مدتی شنیده نمی‌شود.

## امنیت

- هر کار از همان هندلرهای API پنل رد می‌شود، داخل خود برنامه: همان بررسی‌ها،
  همان قفل‌های Pro و همان لاگ ممیزی صفحه‌ی پنل (خط‌های ممیزی `via_telegram`
  دارند).
- حذف تونل یا مشتری، بازگردانی نسخه پشتیبان، آپدیت، تعمیر سریع، تنظیمات شبکه،
  ری‌استارت همه‌ی تونل‌ها و هر تغییری با `/api` با یک **دکمه‌ی یک‌بارمصرف که ۲
  دقیقه اعتبار دارد** دوباره پرسیده می‌شود، و فقط حسابی که دکمه برایش آمده
  می‌تواند آن را بزند.
- پیام‌هایی که وقتی پنل خاموش بوده به ربات رسیده، موقع روشن شدن دور ریخته
  می‌شوند؛ پس یک دستور قدیمی بعد از ری‌استارت هرگز اجرا نمی‌شود.
- توکن هیچ‌وقت در لاگ یا خطا دیده نمی‌شود.

## چه کارهایی نمی‌شود

- **ترمینال سرور.**
- **ورود، تغییر رمز، 2FA و تنظیمات دسترسی پنل** (پورت، نام کاربری، مسیر).
- **وارد کردن کلید لایسنس** (فقط از پنل)، یا تبدیل پنل به node core.
- **ساختن تونل یا مشتری با ویزارد.** آن‌ها را در پنل بسازید (یا با `/api` اگر
  بدنه‌ی درخواست را می‌دانید).
- **آپلود فایل**، مثل گواهی TLS دلخواه یا نسخه پشتیبانی که روی کامپیوتر خودتان
  است. بازگردانی نسخه‌ای که روی سرور هست کار می‌کند.
- **نمودارها**: فقط متن.
- **اداره‌ی نودهای دیگر**: ربات هر سرور فقط همان سرور را اداره می‌کند (ربات پنل
  مرکزی نودها را نشان می‌دهد).
- **وقتی سرور به تلگرام نمی‌رسد** (بسته است و همه‌ی تونل‌ها هم قطع‌اند) ربات تا
  وصل شدن دوباره جواب نمی‌دهد و هشدارها هم نمی‌رسند.
- کارهای طولانی (آپدیت، اجرای عیب‌یابی) وقتی تمام شوند جواب می‌دهند؛ تا آن
  موقع «⏳» نشان داده می‌شود.
