# Error codes

> Generated by `tools/gen_docs.py` from `panel/errors.go`. Do not edit by hand.

Every backend failure carries a stable code. You see it in the UI toast, in API replies, in
`GET /api/errors` (a small on-disk journal), and as an annotation on raw FRP / GRE / Backhaul log
lines in the Logs tab. `HTTP 0` means the code is a log annotation, not an HTTP reply.

## E-FRP-xx — FRP diagnostics

| Code | HTTP | Meaning | What to do |
| --- | --- | --- | --- |
| `E-FRP-01` | — | frps service not active | Start it from the peer card (Restart) or check its log. |
| `E-FRP-02` | — | frp authentication failed (token mismatch) | Re-copy the token from the Iran peer card to the Foreign side. |
| `E-FRP-03` | — | frp bind conflict (address already in use) | Another tunnel uses this port — change frp_port or the reverse port. |
| `E-FRP-04` | — | frp cannot reach server (connection refused/timeout) | Iran unreachable: wrong IP/port, firewall, or frps down. |
| `E-FRP-05` | — | file descriptor limit reached (too many open files) | Process hit LimitNOFILE. Ensure LimitNOFILE=1048576 in systemd and kernel fs.file-max. |
| `E-FRP-06` | — | heartbeat timeout (FRP control link dropped) | Network jitter or heavy bandwidth contention delayed heartbeat packets. Heartbeat timeout relaxed to 90s. |
| `E-FRP-07` | — | connection reset by peer / broken pipe | Remote peer or network carrier reset the TCP stream. |
| `E-FRP-08` | — | connection tracking table full (packet dropped) | Kernel nf_conntrack_max limit reached under high concurrent connections. Run Optimize in Tunnel tab. |
| `E-FRP-09` | — | yamux stream capacity / buffer overflow | High stream contention on single TCP mux. Increase poolCount in frpc. |
| `E-FRP-10` | — | frpc login failed with EOF (likely tcpMux mismatch) | tcpMux mismatch: hub is likely tcpMux=true, run `hashem perf tcpmux on\|off` so both ends match (default OFF). |

## E-BH-xx — Backhaul diagnostics

| Code | HTTP | Meaning | What to do |
| --- | --- | --- | --- |
| `E-BH-01` | — | backhaul authentication failed (token mismatch) | The client token differs from the server token. Re-copy it from the Iran side; the token shown in logs is masked. |
| `E-BH-02` | — | backhaul control channel failed (EOF) | Usually a wrong token or a transport mismatch (e.g. tcp vs tcpmux/ws) between hub and spoke. Make both ends use the same transport and token. |
| `E-BH-03` | — | backhaul rejected the config file | The binary does not understand this config dialect (sectioned premium schema vs flat server/client). Re-run the Backhaul setup in `hashem`. |
| `E-BH-04` | — | backhaul transport mismatch: the link is up but carries no data | The two servers use different Backhaul transports of the same family (tcp vs tcpmux, ws vs wsmux): the control channel connects, every connection fails. Set the same transport on both, or set the foreign side up again from the Iran bundle. |
