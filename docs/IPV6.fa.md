# IPv6 در هاشم

[English](IPV6.md)

هاشم از IPv6 در سه جا استفاده می‌کند:

1. **کاربران ← سرور ایران.** کاربران می‌توانند هم با IPv4 و هم با IPv6 به پورت‌های فوروارد شده وصل شوند.
2. **سرور ایران ↔ سرور خارج.** بعضی موتورها می‌توانند دو سرور را از راه IPv6 به هم وصل کنند.
3. **پوشش GRE.** تونل GRE اصلی می‌تواند از روی IPv6 (4in6) یا از روی یک IPv6 خصوصی داخل IPv4 (6to4) برود.

## ۱. کاربران از راه IPv6

تنظیمی لازم نیست. Backhaul، FRP، باقر و Xray روی همه‌ی آدرس‌های هر دو نسخه گوش می‌دهند. اگر سرور ایران IPv6 عمومی داشته باشد و فایروالش پورت‌ها را باز بگذارد، کاربران می‌توانند به `[IPv6]:port` وصل شوند. UFW این کار را برای IPv6 انجام می‌دهد وقتی در `/etc/default/ufw` مقدار `IPV6=yes` باشد، که پیش‌فرض است.

## ۲. اتصال دو سرور از راه IPv6

| موتور | از راه IPv6 | چطور |
| --- | --- | --- |
| Backhaul بدون GRE | بله | راه‌اندازی ← Backhaul ← بدون GRE ← **اتصال دو سرور از طریق: IPv6**. باندل (`bh1_…`) آدرس IPv6 سرور ایران را دارد. |
| باقر (SSH) | بله | آدرس IPv6 سرور خارج را به‌عنوان آدرسش وارد کنید. |
| Xray | بله | آدرس IPv6 سرور مقابل را وارد کنید (در حالت معکوس، به‌عنوان IP عمومی همین سرور). |
| GRE + FRP و GRE + Backhaul | از راه پوشش GRE | خود GRE روی هر دو سرور آدرس IPv4 لازم دارد؛ برای بردنش روی IPv6 از پوشش 4in6 استفاده کنید. |
| Spoof | نه | ذاتاً آدرس مبدأ IPv4 را جعل می‌کند. |

## ۳. GRE روی IPv6: پوشش‌های 6to4 و 4in6

تب تونل ← **پوشش GRE**:

| پوشش | چه چیزی از شبکه رد می‌شود | نیاز |
| --- | --- | --- |
| GRE مستقیم | پروتکل ۴۷ بین آدرس‌های IPv4 | پروتکل ۴۷ رد شود |
| WSS | GRE داخل TLS روی یک پورت TCP | آن پورت TCP رد شود |
| **6to4** | پروتکل ۴۱ بین آدرس‌های IPv4، که یک IPv6 خصوصی /64 را می‌برد و GRE روی آن است | پروتکل ۴۱ رد شود (خیلی وقت‌ها وقتی ۴۷ بسته است) |
| **4in6** | GRE (پروتکل ۴۷) بین آدرس‌های IPv6 عمومی دو سرور | هر دو سرور IPv6 عمومی داشته باشند |

اینترفیس تونل (`gre-tunnel` و `gre-tN`) اسم، آدرس IPv4 داخلی (`10.10.10.x/30`) و مسیرهایش را نگه می‌دارد. پس هر چیزی که روی آن است (FRP، Backhaul، تنظیم MTU و شمارنده‌های ترافیک) بدون تغییر کار می‌کند. در 6to4 یک اینترفیس اضافه هم هست: `hs6-<اسم>`.

**تغییر، هر دو سرور را عوض می‌کند.** دکمه‌ی **تغییر پوشش** اول این سرور را عوض می‌کند و بعد سرور مقابل را از راه Peer Link. برای 4in6، پنل IPv6 عمومی همین سرور را برمی‌دارد و IPv6 سرور مقابل را از خودش می‌پرسد؛ می‌توانید آن را دستی هم وارد کنید. بعد تا ۴۵ ثانیه صبر می‌کند تا آدرس داخلی سرور مقابل جواب بدهد. اگر جواب ندهد، هر دو سرور به پوشش قبلی برمی‌گردند. بدون Peer Link فقط همین سرور عوض می‌شود و سرور دیگر را باید خودتان عوض کنید.

اگر ساختن اینترفیس 6to4 یا 4in6 ممکن نباشد (IPv6 در کرنل خاموش است، یا IPv6 سرور مقابل معلوم نیست)، تونل به GRE ساده برمی‌گردد تا بی‌اینترفیس نماند.

### از خط فرمان

<div dir="ltr">

```bash
hashem carrier set 6to4
hashem carrier set 4in6 --local6 2001:db8::1 --remote6 2001:db8::2
hashem carrier set direct
hashem edit-peer --id 2 --carrier 4in6 --remote6 2001:db8::9
```

</div>

با `--if gre-tN` پوشش فقط روی یک تونل اعمال می‌شود. دو سر هر تونل در `/etc/gre-panel/gre6/<اینترفیس>.env` نگه داشته می‌شود.

### فایروال

- 6to4: پنل پروتکل ۴۱ را از IPv4 سرور مقابل باز می‌کند (`iptables`).
- 4in6: پنل پروتکل ۴۷ را از IPv6 سرور مقابل باز می‌کند (`ip6tables`).
- فایروال ابری جلوی سرور (security group) هم باید همین‌ها را اجازه بدهد.

### MTU

تونل روی MTU 1380 می‌ماند. این هم برای 6to4 جا دارد (۶۴ بایت هدر روی مسیر 1500) و هم برای 4in6 (۴۴ بایت).

## محدودیت‌ها و شمارنده‌های ترافیک

می‌شود سرور خارج را با آدرس IPv6 آن محدود کرد. وقتی تونل GRE روی 4in6 است، IPv6 سرور خارج جزو همان سرعت و حجم IPv4 آن حساب می‌شود. حجم با `ip6tables` شمرده می‌شود و سرعت با `tc ... protocol ipv6` محدود می‌شود. شمارنده‌های هر تونل در داشبورد هم لینک‌های IPv6 را می‌شمارند.

## هنوز روی IPv6 نیست

- رکوردهای DNS کلاستر (فقط A) و متعادل‌کننده‌ی بار آن (فقط IPv4).
- تست مسیر در تب بنچمارک (هنوز پروتکل ۴۱ و IPv6 را تست نمی‌کند).
- تونل Spoof (ذاتاً IPv4).
